# 체크포인트 5 외부 검토와 조치

> 원 제안 당시의 검토 기록이다. 아래의 "판정 불가능", 게인 전반에 대한 단정, 17.6A를 보장 상한으로 읽을 수 있는 표현은 후속 [제안 재검토](006-proposal-review.md)에서 정정했다. 최신 기준은 REQUIREMENTS.md와 STATE.md를 따른다.

대상: 4e4122e(체크포인트 4 감사)까지. 저장소 사용자 요청으로 별도 검토자가 커밋된 파일을 새로 받아 읽고 시뮬레이션 검사를 다시 실행했다. 실행 환경: Linux, CPython 3.12.3, requirements-sim-lock.txt 고정 버전(MuJoCo 3.3.7, BAM 1.0.2). FreeCAD는 없어서 CAD 재생성·간섭·실패 경로 검사는 다시 실행하지 않았다.

## 재실행 증거

- 4e4122e 그대로: 모델 계약, 5초 서 있기, 응답 회귀검사 6개, 6조건 응답 예측이 모두 커밋된 보고서와 일치(마지막 자리 부동소수점 차이만 있음).
- 수정 후: `scripts/run_checks.py` 전체 시뮬레이션 묶음(CAD 제외)이 Linux에서 모두 종료 코드 0. 다만 package_print/render_cad가 3MF 압축 시각과 Linux 글꼴로 바이너리를 다시 만들어 형상과 무관한 바이트 차이가 생겼다. 이 파일들은 커밋된 Windows 산출물로 되돌렸고, reports/checkpoint-validation.json은 그 뒤 `--suite response`로 다시 기록했다.
- `--suite response --require-response-targets`는 예상대로 종료 코드 1(설계 게인에서 빠르기 0/6).

## 발견

1. 응답 기준이 판정 불가능하게 잡혀 있었다. 비례 제어만 쓰는 위치 제어는 하중 τ에서 약 τ×(°/N·m)만큼 처진 채 멈춘다. 4e4122e 보고서에서 0.05N·m는 약 3.0°, 0.1N·m는 약 6.3° 처진다. 하중 상태의 명령 각도 ±0.2° 정착을 수용 기준으로 쓰면, 같은 모델에서 처짐이 게인에 거의 반비례하므로 P 약 12,500(레지스터 최대 16,383)이 필요하다. 그래서 게인·지연·마찰을 바꿔도 판정이 항상 미달이라 다음 결정에 쓸 수 없었다.
2. 서 있기 보고서의 peak_actuator_torque_nm 0.323N·m는 시작 직후 100ms 이내 착지 과도 구간 값이다. 정지 자세에서 무릎은 0.045N·m(정지 토크의 약 9%)를 쓰고 약 3.5° 처진다. 관절별 값이 없어 오해 소지가 있었다.
3. README 폴더 표에 hardware/가 있었으나 폴더가 없었다. 5V 레귤레이터는 CAD의 빈 자리(46×31×10mm·27g)뿐이고, 12개 모터 정지 토크 동시 상한은 5V에서 약 17.6A(1.47A×12, 공식 매뉴얼)다. 전원·부품표 검토가 기록에 없었다.
4. REQUIREMENTS.md R2가 0.6kg으로 남아 README/STATE/design.json의 0.7kg과 달랐다.
5. 서 있기 합격선(최저 높이 70%, 기울기 10° 미만, 발 4개 접촉)은 느슨하다. 이번에는 기준을 바꾸지 않고 관절별 토크·처짐을 보고서에 추가해 드러내기만 했다.

## 조치

- 반응성을 빠르기와 정확도로 분리했다(design.json response_acceptance_targets, control/response_metrics.py, scripts/check_step_response.py). 빠르기 판정: 최초동작 ≤40ms, 실제 도달 변위의 90%까지 ≤150ms. 정확도: 하중당 처짐(°/N·m) 특성화, 보행 정확도 예산 전까지 합격/불합격 없음. 명령 각도 ±0.2° 정착은 진단값으로 남겼다. 회귀검사 3개 추가(총 9개).
- scripts/check_gain_sweep.py와 reports/gain-sweep.json 추가. P 400/800/1600/3200을 비교하되 설계 게인은 바꾸지 않았다.
- scripts/check_sim.py가 관절별 초기 100ms 최대, 이후 최대, 마지막 1초 평균 토크, 정지 토크 대비 비율, 끝 위치 오차를 기록한다. 합격 조건은 그대로다.
- design.json에 power 항목, hardware/README.md에 전원·BOM 미결 항목을 기록했다. 설계는 하지 않았다.
- REQUIREMENTS.md R2를 0.7kg(변경 이력 포함)으로 맞추고 R3을 분리 기준으로 바꿨으며 R7 모터 전원을 추가했다.

## 결과와 한계

- 설계 게인 P 400: 최초동작 21~29ms(목표 이내). 90% 도달 시간은 무부하 178ms, 중력에 맞서는 방향은 최대 1226ms라 빠르기 0/6. 처짐 약 60~63°/N·m.
- P 800: 빠르기 6/6(최대 139ms), 처짐 약 35°/N·m. P 1600: 6/6(최대 83ms), 약 19°/N·m. P 3200: 6/6(최대 72ms), 약 9.6°/N·m.
- BAM은 우리 5V 개체로 맞춘 모델이 아니다. 높은 게인의 떨림·발열·유격을 모델이 반영하지 않으므로 위 비교는 게인 변경 근거가 아니다. 5V 모터 1개에서 최초동작, 90% 도달 시간, 하중당 처짐을 측정해 모델을 맞추는 것이 먼저다. 하드웨어 동작에는 저장소 규칙대로 별도의 명시적 지시가 필요하다.
- 기준 분리는 연구 판정 기준을 바꾸는 변경이다. 저장소 소유자의 승인 뒤 반영한다.
