# 한쪽 뒷다리 배치 검사 재검토

2026-10-24. 구현 `815b2ea`, 재현 수정 `0a59318`. 커밋된 생성 코드와 60mm 모델 XML을 다시 읽고, 커밋 추출본에서 계산을 재생성했다. 모터 선정이나 제작 승인 검토가 아니다.

## 발견과 처리

1. **첫 커밋의 소스 압축본에서 HTML 두 파일의 바이트 재현이 실패했다.** Git 객체에는 LF가 들어 있지만 Windows의 `git archive`가 HTML에 CRLF를 적용했다. 기존 `.gitattributes`에는 Python/JSON/XML/Markdown의 LF 규칙만 있었고 HTML은 빠져 있었다. `*.html text eol=lf`를 추가한 `0a59318`에서 다시 추출·생성하니 아래 7파일이 모두 바이트 일치했다. 입력 JSON만 CRLF로 바꾼 재시험도 일치했다. 이전 체크포인트의 입력 해시 문제와 원인이 다르다.
2. 50mm 링크와 지름 53mm 모터가 겹치는 것, 60mm 링크의 깊은 접힘이 실패하는 것은 계산 오류가 아니라 **현재 배치의 실제 기하적 제약**이다. 해당 자세를 합격으로 숨기지 않았다. 원통 모델 기준이며 실제 제품 상세 외곽과 조립 여유는 별도다.
3. 모터 하우징·발바닥 간격 검사에 흰 링크 표시용 캡슐을 포함하지 않았다. 보고서와 README에 제외 범위를 명시했다. 그림에서 연결이 보이는 것은 체결 가능한 부품 설계의 증거가 아니다. 나사·베어링·배선·껍데기·다른 다리도 미검증이다.
4. 몸통 고정 상태의 좌우 15° 자세에서 발바닥이 기울어진다. 앞뒤 발목 1축으로 독립적인 좌우 발바닥 기울기를 제어할 수 있다는 주장을 하지 않는다. 전체 몸통 자세·발 구조·추가 축을 비교할 문제이며, 이 한 자세로 두 발 보행 자체가 불가능하다고 판단하지 않는다.
5. 몸통을 90° 돌리면 엉덩이 첫 축의 세계 좌표 방향도 바뀐다. 지정한 두 자세를 전형적인 사족/이족 축 배치의 검증으로 취급하지 않는다. 원점의 고정 연결부를 이동해 발의 최저 모서리를 바닥에 맞추는 방법 또한 균형·접촉 가능성을 증명하지 않는다.
6. 관절별 힘은 발바닥 중심의 지정한 수직 힘에 대한 `-JᵀF` 기여분이다. 다리 무게·관성·수평 힘·실제 접촉·전체 균형을 생략했다. 모터 정격과 비교한 수용 판정이나 실물 토크 측정으로 쓰지 않는다.

## 실제 실행한 검사

- MuJoCo 3.3.7. 마디 길이 50/55/60mm, 각 96표본으로 총 288표본. 지정한 별도 표시 자세 5개. 시뮬레이션 시간 전진은 없으며 `mj_forward`, `mj_geomDistance`, `mj_jacSite`로 위치·간격·미분을 계산했다. 충돌 응답을 껐어도 외형 거리는 직접 호출로 검사한다.
- 나란한 세 피치 축 모터 원통의 간격을 `L-D`, `2L*cos(무릎각/2)-D`로 독립 확인했다. 최대 차이 0.000354mm, 허용 0.02mm 이내.
- 관절각 ±1e-7rad 중앙 차분으로 발 위치 미분을 확인했다. 최대 차이 2.60e-10m/rad, 허용 1e-8m/rad 이내. 검사는 힘 예시로 쓰는 지정 자세 3종에 한정된다.
