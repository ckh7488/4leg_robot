# PR #1 제안 재검토

> 후속 최종 검토(007-final-pr-review.md)에서는 미소 도달량을 속도 선별에서도 실패시키도록 강화했다. 아래 기록은 d288669 검토 당시의 상태다.

대상: 원 제안 ca72bf5 및 보완 커밋 d288669. Windows, Python 3.12.14, requirements-sim-lock.txt 고정 버전. 하드웨어를 구동하지 않았다.

## 판단

반응 속도와 하중 정확도를 분리해 측정하는 방향은 타당하다. 다만 최종 위치 추정의 유효성과 명령 추종 오차를 함께 보여야 한다. 기준을 만족하지 못했다는 사실만으로 기존 정확도 요구가 잘못됐다고 결론내릴 수 없다. 따라서 속도 선별 통과를 전체 반응성 수용으로 취급하지 않고 정확도 예산은 미정으로 남긴다.

명령 시점부터 최종 변위의 90%까지 걸린 시간은 지연을 포함한다. 통상적인 10→90% 상승시간과 이름이 비슷해 혼동될 수 있어 정의를 명시했다. [MathWorks stepinfo](https://www.mathworks.com/help/control/ref/dynamicsystem.stepinfo.html)는 초기값·정상상태값에 대한 상승시간과 정착시간을 구분한다.

## 재현한 문제와 수정

1. **지속 진동의 잘못된 속도 합격.** 10ms 간격의 `[0, 0] + [5, 15] * 14`를 10° 명령 응답으로 주면 원 지표는 최초동작 30ms, 90% 도달 40ms였다. 마지막 평균을 정상상태값으로 가정해 계속 진동해도 속도가 통과할 수 있었다. 수정 후에는 마지막 전체 100ms의 범위와 드리프트를 검사하며 이 예제는 속도 무효/null로 기록한다.
2. **짧은 관찰창과 드리프트.** `[0, 5, 10]`처럼 30ms만 관찰한 자료도 원 지표에서는 20ms 도달 시간으로 계산됐다. 전체 관찰창을 요구하고 선형회귀 드리프트도 검사한다. design.json의 범위 0.1° 및 드리프트 1°/s는 기존 선행 정지 판정 수준을 참고한 선별값이다. 유한 관찰창 검사이며 점근 안정성의 증명은 아니다.
3. **작은 움직임과 전체 성능의 혼동.** 10° 명령에 0.2°만 움직이면 속도는 빠를 수 있으나 목표 오차는 9.8°다. 실제 변위/명령 변위 비율과 절대 오차를 보고하고, 정확도·전체 수용 필드를 null(미판정)로 둔다. 속도만 만족할 때 전체 합격이 되지 않는 회귀검사를 추가했다.
4. **불가능성 단정과 고게인 일반화.** 원 문서의 "어떤 게인에서도 불가능"은 입증되지 않았다. 약 P 12,500은 정적 처짐의 역비례 외삽이다. 공식 P 레지스터 범위 0~16,383 안에 있지만 범위 안이라는 사실도 정착 성능을 보장하지 않는다. "P 800 이상"은 실제 시험한 P 800/1600/3200으로 범위를 좁혔다.
5. **전원 상한 표현.** 공식 5V 스톨 전류 1.47A × 12 = 17.64A는 참고 합계다. 이를 실제 피크의 보장 상한이나 레귤레이터 정격으로 확정하지 않는다. Current Limit의 적용은 전류 제어/전류 기반 위치 제어 모드에 의존하므로 일반 위치 제어에서 자동 보호된다고 가정하지 않는다. 근거: [ROBOTIS XL330-M288 매뉴얼](https://emanual.robotis.com/docs/en/dxl/x/xl330-m288/).

## 수치 확인

- P 400은 빠르기 0/6이고 P 800/1600/3200은 각각 6/6이다. 최종 위치 유효성 검사를 추가해도 이 시험들의 속도 판정은 유지됐다.
- 부하 조건 최대 목표 오차는 P 800에서 3.913°, P 1600에서 1.940°, P 3200에서 0.948°다. 이는 속도 통과가 정확도 통과를 뜻하지 않음을 보여준다.
- 원 제안 추출본에서 P 12,518과 P 16,383도 별도로 계산했다. 0.1N·m의 선행 정지 오프셋은 각각 약 0.244°와 0.187°였으나, 두 경우 모두 명령 ±0.2°/150ms 정착은 0/6이다. 정적 처짐의 외삽과 동적 정착은 별개이며 이 두 시험으로 전체 게인 범위의 불가능성을 증명할 수 없다.

고게인 확인은 별도 검사 복사본에서 다음 명령으로 재현한다. 설계 게인과 실기 레지스터는 바꾸지 않는다.

```powershell
python scripts/check_step_response.py --kp 12518 --suffix review-12518
python scripts/check_step_response.py --kp 16383 --suffix review-16383
```

## 검증 범위

- 보완 코드의 회귀검사 16개 통과. 진동, 관찰창 부족, 드리프트, 미소 움직임, 선행 정지 실패와 감지 임계값을 포함한다.
- 응답 전용 실행 묶음 정상 종료. 속도 계산이 불가능한 조건이 있으면 게인 요약은 해당 최대값을 null로 유지하는 것도 확인했다.
- d288669를 별도 폴더에 추출하여 입력·산출물 SHA-256 일치 확인 후 응답 묶음을 재실행했다. 응답·게인 보고서는 커밋된 결과와 상대/절대 허용오차 1e-9 이내 일치했다. `--require-targets`는 예상한 종료 코드 1을 반환했다.
- 같은 추출본에서 P 16,383의 6조건 모두 최종 위치 유효성 실패로 90% 도달 시간을 null로 표시하고 속도 불합격으로 처리하는 것을 확인했다. 높은 게인에서의 불안정한 관찰값을 빠른 응답으로 오해하지 않도록 하는 검사다.
- CAD·보행·Isaac·RL·실물 발열·전원 과도 응답은 이번에 다시 검증하지 않았다. 다음 판단에는 보행 정확도 예산과 실제 5V 모터 보정이 필요하다.
