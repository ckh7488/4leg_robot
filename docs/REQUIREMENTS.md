# 요구사항과 검증 기준

| ID | 요구 | 판정 방식 |
|---|---|---|
| R1 | 총예산 100만원 이하 | BOM + 배송/재출력/예비부품 포함. 실구매 견적은 별도 |
| R2 | 작고 가벼운 4족 | 질량 목표 0.7kg(초기 0.6kg에서 체크포인트 3에 변경); CAD/부품 실제 중량으로 갱신 |
| R3 | 반응성 | 빠르기: 부하 시험의 최초동작 지연·90% 도달 시간·지터. 정확도: 하중당 처짐(°/N·m) 특성화 |
| R4 | MuJoCo/Isaac 연동 | 공통 구동계/관절 계약; 각 엔진에서 실제 실행 여부 구분 |
| R5 | Bambu 출력 | 180mm 베드에 개별 부품 배치 가능; 0.4mm 노즐 적합성/쿠폰 실측 |
| R6 | 감사 가능성 | 출처·생성 코드·원시 결과·한계·커밋 기록 |
| R7 | 모터 전원 | 5V 레일이 12개 모터의 최악 전류를 감당하는지; 레귤레이터·배터리·배선 선정과 전압 강하 실측 |

반응성은 빠르기와 정확도를 분리한다. 둘 다 설계 목표이며 실측 전 보장하지 않는다.

- 빠르기 수용 목표: 최초동작 p95 ≤40ms, 부하 10도 명령에서 실제 도달 변위의 90%까지 명령 시점부터 p95 ≤150ms. 후자는 지연을 포함한 0→90% 도달 시간이며 통상적인 10→90% 상승시간과 다르다.
- 도달 변위 기준값은 마지막 100ms 전체의 범위 ≤0.1°, 선형회귀 드리프트 ≤1°/s를 만족할 때만 사용한다(design.json). 이는 유한 관찰창의 선별 조건이며 점근 안정성이나 정확도를 보장하지 않는다. 진동·짧은 관찰창·잘못된 방향의 응답은 속도 합격으로 계산하지 않는다.
- 속도 평가에는 명령 변위의 최소 50%를 같은 방향으로 실제 이동해야 한다(min_reached_command_fraction). 거의 움직이지 못하는 응답의 합격을 막는 보수적인 연구용 하한이며, 50% 도달을 정확도 합격으로 인정하는 기준은 아니다. 샘플 간격이 관찰창 경계와 맞지 않으면 경계 직전 표본을 포함해 전체 100ms를 확인한다.
- 정확도: 하중당 처짐(°/N·m)을 특성화한다. 보행 정확도 예산을 정하기 전까지 합격/불합격 기준을 두지 않으며, 시뮬레이션이 5V 실측값을 재현하는지가 판단 대상이다.
- 명령 각도 ±0.2° 정착은 진단값으로 계속 기록한다. 현재 P-only 모델의 하중 처짐은 크지만 이 기준 자체가 잘못됐거나 모든 게인에서 불가능한 것은 입증하지 않았다. 약 P 12,500은 정적 처짐의 역비례 외삽일 뿐, 검증된 필요 게인이나 150ms 정착 보장이 아니다.
- 속도만 통과해도 전체 반응성이 승인된 것은 아니다. 실제 변위/명령 변위 비율과 절대 목표 오차를 함께 보고하며, 정확도 예산·실측 검증 전에는 accuracy_target_met와 overall_response_accepted를 null(미판정)로 둔다. 10° 명령에 0.2°만 빠르게 움직이는 응답은 속도 선별에서도 실패한다.
- 변경 이력: 체크포인트 4까지는 "부하 10도 명령의 명령 각도 ±0.2° 정착 p95 ≤150ms"를 단일 기준으로 썼다. 체크포인트 5의 분리는 속도·하중 정확도·모델 오차를 따로 진단하기 위한 수용 기준 변경 제안이다. 미달 결과 자체는 정확도 요구를 없애는 근거가 아니다. 기어 유격, 온도, 공급전압, 부하와 측정 정의를 함께 저장한다.
