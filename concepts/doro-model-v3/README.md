# 도로롱 전신 관절 모델 V3

[3차원 동작 화면 열기](index.html). 인터넷 연결 없이 폴더 안의 `index.html`을 브라우저로 연다. 마우스로 회전, 휠로 확대한다. 외형·투명·관절 표시를 바꾸고 19개 관절을 직접 조작할 수 있다.

완료 범위는 **연결된 전신 관절 트리, 캐릭터 외형, 모터 공간, 동작 미리보기, MuJoCo/URDF 내보내기**다. 제작용 CAD나 균형 제어기의 완성이 아니다. 두 발 보행·네 발 보행·넘어짐 복구·외부 전원 당김 측정 요구를 유지한다. 자가복구와 전진 보행 애니메이션은 아직 제공하지 않는다.

## 관절과 치수

| 부위 | 움직임 | 개수 |
|---|---|---:|
| 뒷다리 | 골반 방향·벌림·앞뒤, 무릎, 발목 앞뒤·좌우 | 6 × 2 |
| 앞다리/팔 | 어깨 벌림·앞뒤, 앞으로 접히는 팔꿈치 | 3 × 2 |
| 목 | 고개 끄덕임 | 1 |

세운 기준 자세의 외형 높이는 약 78cm, 머리 양쪽 장식까지 폭 약 62cm다. 뒷다리 마디는 14+15cm, 앞다리는 16+18cm다. 질량 **16.272kg은 부품별 할당 예산**이며 실측·제작 CAD 계산값이 아니다. 원통은 참고 BLDC 모터의 공간이며 확정 구매품이 아니다. 크기와 비용을 우선 제한하지 않은 현재 구조 탐색안이다.

V2의 한 점에 모인 골반/어깨 축을 실제 거리만큼 떨어뜨렸다. 어깨를 몸통 앞·바깥으로 옮기고 벌림 범위를 ±110°로 가정했다. 팔꿈치는 앞쪽으로 접는다. 몸통 속 고정 프레임 공간은 골반 모터를 피하도록 좁혔다. 모터 장착부·베어링·배선 개구부·기계적 관절 멈춤쇠는 추가 설계가 필요하다.

## 동작과 검사 범위

화면은 두 발 서기, 리듬 춤, 팔 벌리기/모으기, 앉았다 펴기, 제자리걸음, 두 발↔네 발 전환, 네 발 자세를 제공한다. 몸통 경로를 미리 정하고 손발 위치에 맞춰 관절을 계산한다. **지면 반력을 받아 스스로 균형을 유지하는 시뮬레이션이 아니다.** 재생 속도도 모터 실측 반응 속도가 아니다. 영상의 느낌을 지면 위 동작으로 재구성했으며 원본의 자세/속도를 추정해 복제하지 않았다.

- 24표본/초, 총 583자세에서 손발 위치 오차 최대 약 0.002mm, 관절 범위 확인. 이것은 역기구학 계산의 수치 오차다.
- 검사한 충돌 도형의 1mm 초과 겹침·바닥 침범 없음. 자동 접촉에서 빠지는 이웃/같은 링크의 모터도 19개 원통의 모든 쌍을 별도로 검사했다.
- 독립 URDF 관절 계산과 MuJoCo의 링크 위치/방향을 전체 동작 및 추가 무작위 32자세에서 대조했다.
- 자유몸체에 입력 없이 0.2초 계산이 정상 진행됨을 확인했다. 몸통 높이는 35.5cm에서 약 22.8cm로 내려간다. 서 있기 통과 시험이 아니다.
- 검사하지 않은 것: 표본 사이 연속 경로의 모든 간격, 외피·배선·체결부, 실제 모터 힘/열/지연, 균형과 자가복구. 수동 슬라이더로 만든 임의 자세도 미검사다.

흰 외피/분홍 머리카락은 비율 확인용 표면이며 충돌 도형에서 제외했다. 중공 외피의 실제 두께·구멍이 없으므로 이 화면으로 외피 제작 적합성을 판단하지 않는다. 주황 점은 할당 질량으로 계산한 무게중심, 초록 점은 동작에서 지정한 손발 목표다. 직접 조작할 때는 목표 점을 숨기고 무게중심을 다시 계산한다.

## 파일과 재현

- `design.json`: 이 모델의 치수·질량·범위·미검증 가정.
- `build_model.py`: 하나의 관절 트리에서 `model.json`, `robot.xml`, `robot.urdf`, 공용 구 메시 생성.
- `build_motions.py`: 손발 목표, 역기구학, 동작 경로와 표본 검사. 생성 전 모델도 재생성한다.
- `motions.json`, `motion_validation.json`: 동작과 모드별 결과.
- `validate.py`, `validation.json`: 독립 모델 대조, 전체 모터 쌍 검사, 수치 계산 점검.
- `model-data.js`, `viewer.js`, `index.html`: 오프라인 화면.
- `check_viewer.cjs`, `browser_samples.json`: 실제 브라우저와 MuJoCo 위치 대조 및 조작 검사.

저장소 루트에서 NumPy, MuJoCo 3.3.7, trimesh 5.1.1이 있는 Python 환경으로 실행한다. trimesh는 단위 구 메시 생성에 사용한다.

```text
python concepts/doro-model-v3/build_motions.py
python concepts/doro-model-v3/validate.py
python concepts/doro-model-v3/test_validation.py
node concepts/doro-model-v3/check_viewer.cjs outputs/doro-v3
```

화면 검사는 Node.js의 `playwright`와 Microsoft Edge가 필요하다. 검사 출력·스크린샷은 지정한 출력 폴더에 기록한다. Python 검사에만 브라우저가 필요한 것은 아니다. MuJoCo `stand`/`quad` keyframe에서 각각 시작할 수 있다. URDF의 루트 링크는 `base`이며 전역 몸통 위치는 소비하는 프로그램에서 설정한다.

모터 원통이 정확히 포개질 때 MuJoCo의 거리 함수가 0을 반환하는 경우를 발견했다. 각 원통 내부에 들어가는 구의 겹침으로 보완하여 이 경우도 거부한다. 정확한 겹침·부분 겹침·분리된 원통의 회귀검사 3개를 제공한다.

## 물리 모델의 가정

질량과 상자 기반 관성은 할당값이다. 출력축 토크 입력 ±30N·m, URDF 속도 한계 20rad/s, 마찰·감쇠·회전자 등가 관성은 **실제 모터에서 확인한 성능이 아닌 임시값**이다. 앞뒤/좌우 발목을 독립 출력축처럼 표현했다. V2의 두 막대 전달 기구와 실제 모터 회전은 새 치수에 맞춰 다시 연결해야 한다. 팔꿈치/무릎 원격 모터의 벨트·지지대도 아직 외형 공간만 있다. 케이블 소켓은 위치 표시이며 전원/장력 센서 모델은 미구현이다.

다음 실질 작업은 외피 개구부와 전달 장치의 기구 배치, 실제 모터 특성, 균형 제어를 연결하여 한 발 지지·보행·복구 가능성을 검사하는 것이다.
