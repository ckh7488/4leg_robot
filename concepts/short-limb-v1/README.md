# 짧은 팔다리 로봇 — 형상 탐색 V1

사용자의 2026-10-24 방향 수정: 참고 이미지처럼 큰 얼굴과 아주 짧은 팔다리, 빠른 반응, 네 발 보행에 더해 **두 발로 걷기**, 넘어진 뒤 스스로 복구. BLDC 관절을 검토한다. 초기에는 외부 직류 전원과 케이블 당김 측정을 사용한다. 200만원은 판단 기준점이며 절대 상한이 아니다.

[그림과 계산 보기](concept.html). 이 폴더의 `design.json`은 **새 개념 설계의 가정 원본**이며, 루트 `design.json`은 기존 XL330 구현의 원본이다. 기존 모델의 시험 결과를 새 구조에 재사용하지 않는다.

## 현재 만든 것

- 사용자 이미지의 비율을 참고한 외형 그림. 내장 image_gen으로 생성했으며 프롬프트는 `image-prompt.txt`에 저장했다. 정밀 기구 설계가 아니다.
- 두 발 높이 28–36 cm, 겉으로 보이는 팔다리 5–8 cm, 실제 엉덩이~발목 링크 합 10–12 cm의 **탐색 범위**. 한쪽 뒷다리 모터 원통 외형은 아래에서 검사했다. 전체 몸체·배선·베어링 배치는 미검증이다.
- 12관절 비교안과 뒷발목 앞뒤 축을 더한 14관절 우선 검토안. 두 안 모두 머리 기울기 1축을 추가하면 총 13/15축이다. 실제 축 방향·가동 범위는 미확정이다. 앞뒤 발목만으로 좌우 발바닥 기울기까지 제어할 수는 없다.
- 단순 정적 힘·모터 수에 따른 질량 예산·케이블 힘의 영향. 다리 짧음이 두 발 보행의 토크 문제를 자동 해결하지 않는다는 것을 수치로 기록했다.

## 설계에서 지킬 점

1. 큰 머리는 가벼운 껍데기. 무거운 부품은 몸통 아래쪽에 모은다. 머리를 기울일 때의 무게중심 이동과 목 충돌도 계산한다.
2. 같은 하중과 자세 비율이면 짧은 다리는 지레 길이를 줄이는 데 유리하지만, 한 발 지지에는 거의 전체 몸무게가 걸린다. 실제 관절별 힘은 지면 반력과 관절 축·자세를 사용해 계산한다.
3. 짧은 다리는 보폭·장애물 여유도 줄인다. 같은 보행 속도를 원하면 관절 회전속도와 동작 빈도가 증가할 수 있다.
4. 큰 껍데기 때문에 짧은 앞발이 바닥에 닿지 않으면 자가복구가 불가능할 수 있다. 옆면/등이 바닥에 닿은 자세를 각각 검사한다.
5. 외부 전원 케이블은 몸을 들어 주지 않는 조건에서 검증한다. 힘을 보정하려면 당김 크기·방향·연결 위치가 필요하다. 전동 릴, 회생 전력, 전압 강하는 미설계다.
6. 고정된 얼굴을 몸통과 함께 세우면 얼굴도 위로 향할 수 있다. 외형 그림은 두 자세에서 얼굴이 앞을 보이므로 별도 머리 기울기 축을 예산에 포함했다. 실제 연결은 미설계다.

## 계산의 한계와 재현

저장소 루트에서 Python 표준 라이브러리만으로 실행한다.

```sh
python concepts/short-limb-v1/screen_design.py
```

`screening.json`과 `concept.html`을 재생성한다. 질량 3/4/5 kg, 수평 지레 길이 3/6 cm, 같은 비율로 받치는 발 4/2/1개의 18조건을 계산한다. 식은 `(질량 × 중력 / 지지 발 수) × 선택 관절의 수평 지레 길이`다. 다리 전체 길이를 지레 길이로 대체한 것이 아니다. 가속·충격·다리 무게·수평 힘을 생략한 기여분이므로 모터 정격을 선정하는 계산이 아니다.

질량 시나리오는 제조사/판매처의 모듈 질량에 **기타 1.2 kg 가정**을 더했다. 이 가정에는 작은 머리 구동기 60 g도 포함한다. 외부 전원 장치·외부 릴·배터리는 포함하지 않는다. 제조사 사양은 독립 실측과 구분한다. 가격과 총견적은 이번 개념 단계에서 미확인이다.

단일 회전 막대의 끝 속도 계산은 여러 관절 다리의 보행 속도 계산이 아니다. 제작용 CAD 배치·강도·접촉·자유몸체 시뮬레이션·보행·자가복구·실물 시험은 하지 않았다.

실물 전이와 회생 전력 등의 출처 및 확인일은 `design.json`에 있다. 2024년의 biped walking 연구(arXiv:2407.02282)는 시뮬레이션 결과이며 실물 성공으로 인용하지 않는다.

## 한쪽 뒷다리 배치 검사 · 체크포인트 7

[그림으로 보기](rear-leg/index.html). `design.json`의 `rear_leg_packaging`에 치수·축·가동 범위·지정 자세를 기록했다. 참고 원통은 AK40-10 V3의 지름 53mm / 길이 40.2mm이며 해당 모터를 선정한 것이 아니다.

- 네 축: 몸통을 세운 좌표계의 엉덩이 좌우 축, 엉덩이 앞뒤 축, 무릎 앞뒤 축, 발목 앞뒤 축. 몸통 연결부를 90° 돌리면 첫 축의 공간 방향도 바뀐다. 실제 사족 보행용 축 배치로 확정하지 않는다.
- 마디 길이 50/55/60mm × 몸통 방향 2종 × 좌우 각도 3종 × 앞뒤 엉덩이 각도 4종 × 무릎 각도 4종 = 288표본. 모터 네 원통과 발바닥 상자의 모든 쌍, 모터-바닥 간격을 검사했다. 2mm 간격은 임시 선별 기준이다.
- 50mm 마디는 지름 53mm 모터와 이웃하여 3mm 겹친다. 55mm는 2mm, 60mm는 7mm가 남는다. 다만 60+60mm도 무릎을 140° 접으면 엉덩이와 발목 모터가 약 11.96mm 겹친다.
- 60+60mm / 무릎 70° 및 110°의 지정 자세에서는 검사한 외형 간격이 2mm 이상이다. 몸통 고정 상태에서 다리를 옆으로 15° 기울이면 발바닥 모서리 높이 차가 15.53mm다. 이것은 보행 불가능 판정이 아니라 몸통 자세와 발 구조를 함께 설계해야 한다는 제약이다.
- 전체 질량 4kg을 한 발이 받치는 수직 힘의 기여분만 계산하면, 무릎 70° / 110° 예시의 무릎 토크 크기는 0.96 / 1.54 N·m다. 실제 필요 토크 또는 연속 정격이 아니다.

저장소의 `requirements-sim-lock.txt` 환경에서 실행한다.

```sh
python concepts/short-limb-v1/check_rear_leg.py
python concepts/short-limb-v1/check_rear_leg.py --no-render
```

첫 명령은 `rear-leg/`의 XML 3개, 결과 JSON, HTML, PNG 5개를 생성한다. 두 번째는 이미지 생성만 생략한다. 모터 간격을 독립 기하식과 비교하고, 발 위치의 관절각 미분을 중앙 차분과 비교한다. 각도 입력은 도 단위, 내부 계산은 미터·라디안이다. 모델은 연결부가 고정되어 있고 구동기가 없으며, 충돌 응답은 꺼져 있다. `mj_geomDistance`를 직접 호출해 지정 외형 사이 거리를 계산한다. `mj_step`은 호출하지 않는다.

흰 연결 막대는 위치 표시용이며 간섭 검사 대상이 아니다. 체결부·베어링·배선·모터의 상세 외곽·껍데기·다른 다리는 빠져 있다. 발의 최저 모서리를 바닥에 맞추는 변환은 접촉 안정성을 증명하지 않는다. 원통과 발의 질량, 막대 질량은 표시용 모델 값이며 전체 질량·관성 산출에 사용하지 않았다. 표본 사이의 무충돌도 보장하지 않는다.

다음은 **발목 모터를 위로 옮기는 전달 구조와 옆으로 엇갈리는 배치 비교**, 전체 몸체와 네 다리의 도달/간섭 검사다. 이어 자유몸체에서 한 발 지지·자세 전환·누운 상태의 복구 궤적을 검사한다.
