# 짧은 팔다리 로봇 — 형상 탐색 V1

사용자의 2026-10-24 방향 수정: 참고 이미지처럼 큰 얼굴과 아주 짧은 팔다리, 빠른 반응, 네 발 보행에 더해 **두 발로 걷기**, 넘어진 뒤 스스로 복구. BLDC 관절을 검토한다. 초기에는 외부 직류 전원과 케이블 당김 측정을 사용한다. 200만원은 판단 기준점이며 절대 상한이 아니다.

[그림과 계산 보기](concept.html). 이 폴더의 `design.json`은 **새 개념 설계의 가정 원본**이며, 루트 `design.json`은 기존 XL330 구현의 원본이다. 기존 모델의 시험 결과를 새 구조에 재사용하지 않는다.

## 현재 만든 것

- 사용자 이미지의 비율을 참고한 외형 그림. 내장 image_gen으로 생성했으며 프롬프트는 `image-prompt.txt`에 저장했다. 정밀 기구 설계가 아니다.
- 두 발 높이 28–36 cm, 겉으로 보이는 팔다리 5–8 cm, 실제 엉덩이~발목 링크 합 10–12 cm의 **탐색 범위**. 모터 외형·배선·베어링 배치는 아직 검사하지 않았다.
- 12관절 비교안과 뒷발목 앞뒤 축을 더한 14관절 우선 검토안. 두 안 모두 머리 기울기 1축을 추가하면 총 13/15축이다. 실제 축 방향·가동 범위는 미확정이다. 앞뒤 발목만으로 좌우 발바닥 기울기까지 제어할 수는 없다.
- 단순 정적 힘·모터 수에 따른 질량 예산·케이블 힘의 영향. 다리 짧음이 두 발 보행의 토크 문제를 자동 해결하지 않는다는 것을 수치로 기록했다.

## 설계에서 지킬 점

1. 큰 머리는 가벼운 껍데기. 무거운 부품은 몸통 아래쪽에 모은다. 머리를 기울일 때의 무게중심 이동과 목 충돌도 계산한다.
2. 같은 하중과 자세 비율이면 짧은 다리는 지레 길이를 줄이는 데 유리하지만, 한 발 지지에는 거의 전체 몸무게가 걸린다. 실제 관절별 힘은 지면 반력과 관절 축·자세를 사용해 계산한다.
3. 짧은 다리는 보폭·장애물 여유도 줄인다. 같은 보행 속도를 원하면 관절 회전속도와 동작 빈도가 증가할 수 있다.
4. 큰 껍데기 때문에 짧은 앞발이 바닥에 닿지 않으면 자가복구가 불가능할 수 있다. 옆면/등이 바닥에 닿은 자세를 각각 검사한다.
5. 외부 전원 케이블은 몸을 들어 주지 않는 조건에서 검증한다. 힘을 보정하려면 당김 크기·방향·연결 위치가 필요하다. 전동 릴, 회생 전력, 전압 강하는 미설계다.
6. 고정된 얼굴을 몸통과 함께 세우면 얼굴도 위로 향할 수 있다. 외형 그림은 두 자세에서 얼굴이 앞을 보이므로 별도 머리 기울기 축을 예산에 포함했다. 실제 연결은 미설계다.

## 계산의 한계와 재현

저장소 루트에서 Python 표준 라이브러리만으로 실행한다.

```sh
python concepts/short-limb-v1/screen_design.py
```

`screening.json`과 `concept.html`을 재생성한다. 질량 3/4/5 kg, 수평 지레 길이 3/6 cm, 같은 비율로 받치는 발 4/2/1개의 18조건을 계산한다. 식은 `(질량 × 중력 / 지지 발 수) × 선택 관절의 수평 지레 길이`다. 다리 전체 길이를 지레 길이로 대체한 것이 아니다. 가속·충격·다리 무게·수평 힘을 생략한 기여분이므로 모터 정격을 선정하는 계산이 아니다.

질량 시나리오는 제조사/판매처의 모듈 질량에 **기타 1.2 kg 가정**을 더했다. 이 가정에는 작은 머리 구동기 60 g도 포함한다. 외부 전원 장치·외부 릴·배터리는 포함하지 않는다. 제조사 사양은 독립 실측과 구분한다. 가격과 총견적은 이번 개념 단계에서 미확인이다.

단일 회전 막대의 끝 속도 계산은 여러 관절 다리의 보행 속도 계산이 아니다. 정적 비교와 질량 산술만 실행했으며, CAD 배치·강도·접촉·자유몸체 시뮬레이션·보행·자가복구·실물 시험은 하지 않았다.

다음 관문은 **실제 관절 축과 모터 외형을 넣은 두 자세의 배치/간섭/발 도달 검사**, 그다음 한 발 지지와 복구 궤적의 힘 계산이다. 실물 전이와 회생 전력 등의 출처 및 확인일은 `design.json`에 있다. 2024년의 biped walking 연구(arXiv:2407.02282)는 시뮬레이션 결과이며 실물 성공으로 인용하지 않는다.
